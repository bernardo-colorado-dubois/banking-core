FUNCIONALIDADES

Lo que ya hace

Un core mínimo, pero con las piezas que importan: acceso, cuentas, operaciones y un libro que siempre cuadra.

Usuarios y acceso

Login con JWT, cambio de contraseña obligatorio en el primer ingreso, perfil y alta de administradores y operadores.

Permisos, nunca roles

Tres roles fijos, cada uno con permisos de la forma (acción, alcance). La autorización nunca pregunta por el rol.

Apertura de cuentas

Alta de cliente con su primera cuenta, cuentas adicionales para un cliente existente y cuentas propias del banco.

Operaciones atómicas

Fondeo, retiro y transferencia entre cuentas del mismo banco: se registran todos sus movimientos o ninguno.

Saldo e historial

Los movimientos de una cuenta con el saldo que dejó cada uno, calculado en SQL por la vista historial_cuentas.

Concurrencia segura

Bloqueo de filas con SELECT … FOR UPDATE para que dos operaciones simultáneas no gasten el mismo saldo.

MODELO CONTABLE

Cada cuenta cuadra consigo misma

Toda cuenta tiene dos lados en el libro: el principal, que es el saldo que ve el titular, y la contrapartida, que representa el exterior. El principal es de naturaleza acreedora: un crédito lo aumenta y un débito lo disminuye.

ARQUITECTURA

El viaje de un fondeo

El código se organiza por módulos de negocio, user y account, y las dependencias apuntan hacia el dominio. Esto es lo que pasa en POST /account/{id}/fondeo:

1

@authenticated JWT

Valida el token y consulta al usuario en cada solicitud: una desactivación surte efecto de inmediato.

2

routes.py RUTA

Lee el JSON y revisa los campos obligatorios. Sin reglas de negocio.

3

SELECT … FOR UPDATE BLOQUEO

Bloquea la cuenta antes de calcular el saldo: dos operaciones simultáneas no gastan el mismo dinero.

4

autorizar(acción, alcance) RBAC

Permisos, nunca roles: FONDEAR sobre cuentas propias, de clientes o del banco.

5

Transaction.validar() DOMINIO

Arma los movimientos y aplica las 5 invariantes antes de persistir.

6

COMMIT POSTGRESQL

Transacción y movimientos en un solo commit, que libera el bloqueo.

Sin float

Decimal en Python y NUMERIC(18,2) en la base. La API devuelve los montos como texto con 2 decimales.

Sin deadlocks

Una transferencia bloquea ambas cuentas siempre en el mismo orden, por id.

Un servicio por operación

No uno por rol: el mismo AccountFunder atiende al cliente y al admin. La diferencia la resuelve el alcance de la cuenta.

ROLES Y PERMISOS

Un permiso es el par (acción, alcance)

Los alcances son PROPIAS (las cuentas del usuario autenticado), VOSTRO (cualquier cuenta de cliente) y NOSTRO (las cuentas del banco). En una transferencia el permiso se evalúa solo sobre la cuenta origen.

PUESTA EN MARCHA

Cinco pasos para levantarlo

Se necesita Python, Docker y PostgreSQL 15 o superior; el contenedor del proyecto usa PostgreSQL 17.

# 1. Variables de entorno
cp .env.example .env            # y ajustar los valores

# 2. Dependencias
python -m venv venv
venv/bin/pip install -r requirements.txt

# 3. Base de datos
docker compose up -d

# 4. Esquema, roles, permisos y primer admin
venv/bin/python create_admin.py

# 5. Servidor de desarrollo en http://localhost:8080
venv/bin/python app.py
create_admin.py es destructivo: borra y recrea todas las tablas y la vista historial_cuentas. Hoy es la única forma de crear el esquema, porque todavía no hay migraciones.

PENDIENTES

Lo que todavía no hace

Siguen abiertos en la especificación y no están implementados.

  • Reversos de transacciones.
  • Idempotencia de operaciones, con una clave por solicitud.
  • Migraciones del esquema.
  • Pruebas automatizadas.
  • Servicios para desactivar usuarios o cambiarles el rol.
  • Paginación del historial de movimientos.
